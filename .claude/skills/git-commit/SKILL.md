# Git Commit

이 스킬은 커밋 작업을 **`git-committer` 서브에이전트(haiku)** 에 위임하는 래퍼다.
실제 커밋 컨벤션·실행 절차·규칙은 `git-committer` 서브에이전트 정의에 들어 있으므로
여기서 중복 설명하지 않는다. 서브에이전트는 비대화형이라 사용자 승인은 메인에서 받는다.

## 실행 절차

### Step 1: 제안 받기 (서브에이전트 호출 — commit 금지)

Agent 도구로 `git-committer`(subagent_type)를 호출한다. 프롬프트에:

- 변경 사항을 분석해 **커밋 메시지만 제안하고, 절대 커밋/푸시하지 말라**고 지시한다.
- `$ARGUMENTS`가 있으면 커밋 메시지 힌트로 함께 전달한다.

서브에이전트가 돌려준 제안 메시지를 받는다.

### Step 2: 사용자 확인

제안 메시지를 사용자에게 보여주고 승인을 받는다.

```
다음 메시지로 커밋하겠습니다:

  <제안 메시지>

진행할까요? [y] 승인 / [n] 취소 / 수정할 내용 직접 입력
```

- `n` 이면 중단한다.
- 사용자가 수정 내용을 입력하면 그 메시지로 확정한다(필요하면 다시 확인).

### Step 3: 실행 위임 (같은 서브에이전트 이어가기)

SendMessage로 **Step 1에서 호출한 같은 `git-committer`** 에 이어서 지시한다
(컨텍스트 유지). 승인된 최종 메시지를 전달하고:

- `git add .` → `git commit` → `git push` 를 수행하라.
- 현재 브랜치가 버전 브랜치(v1/v2/v3 등)면 main 으로 `--ff-only` 동기화까지 하라.

### Step 4: 결과 보고

서브에이전트가 반환한 push 결과와 최근 커밋 3개를 사용자에게 전달한다.

## 규칙

- 사용자 승인 없이 커밋·푸시하지 않는다.
- 커밋 컨벤션과 금지 사항(`Co-authored-by`/`Claude` 트레일러 금지, `--no-verify`·`--force` 금지)은
  `git-committer` 서브에이전트가 따른다.
- 자동 트리거되지 않는다 — 반드시 `/git-commit` 으로 명시 호출해야 실행된다.
